## 1. ما هو البوت؟

**Azkar Bot** بوت تيليغرام عربي يذكّر المستخدم بأذكار الصباح والمساء في الوقت الذي يختاره، بنسختين:

- **مختصر** (`short`): ورد أقصر.
- **كامل** (`full`): ورد أوسع يعيد استخدام نفس أذكار المختصر ويضيف المزيد.

كذلك يوفّر قسم **أذكار إضافية** اختيارية موثّقة، يفتحها المستخدم بنفسه (لا تُرسل تلقائيًا كتذكير).

المحتوى الديني منقول بلفظه من مصادره في ملفات تحريرية، **بلا اختراع فضل أو عدد أو توقيت**.

## 2. المبادئ والمنتج

| مبدأ | التطبيق في الكود |
|---|---|
| عربي أولًا | اللغة مفروضة `ar`، وكل واجهة المستخدم في `lang/ar/bot.php` |
| هادئ بلا منافسة | لا ترتيب ولا نقاط ولا streaks؛ زر ✅ تم اختياري فقط |
| دقة دينية | المزامنة من ملفات seed ثابتة المفتاح؛ لا حذف للصفقات القديمة تلقائيًا |
| موثوقية التذكير | ادّعاء (claim) + تقدّم الموعد التالي في معاملة DB واحدة؛ منع التكرار بقيد فريد يومي |
| فصل المسؤوليات | الـ webhook يحفظ فقط؛ المنطق في الـ queue؛ الإرسال في job مستقل |

## 5. طبقات المعمارية

```text
┌─────────────────────────────────────────────────────────────┐
│  تيليغرام (مستخدم ↔ Bot API)                               │
└───────────────┬─────────────────────────────▲───────────────┘
                │ webhook أو getUpdates        │ sendMessage
                ▼                             │
┌───────────────────────────────┐   ┌─────────────────────────┐
│ HTTP: TelegramWebhookController│   │ TelegramClient          │
│ + VerifyTelegramWebhookSecret │   │ parse_mode = HTML       │
└───────────────┬───────────────┘   └───────────▲─────────────┘
                │ persist + 200                   │
                ▼                                 │
┌───────────────────────────────┐                 │
│ telegram_updates (pending)    │                 │
└───────────────┬───────────────┘                 │
                │ ProcessTelegramUpdateJob        │
                ▼                                 │
┌───────────────────────────────┐                 │
│ TelegramUpdateProcessor       │─────────────────┘
│ أوامر / أزرار / إعداد         │
└───────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ Cron: schedule:run كل دقيقة                                  │
│  → adhkar:dispatch-due-reminders                             │
│  → adhkar:recover-stale (كل 5 دقائق)                         │
│  → ReminderDispatchService → reminder_logs → SendAdhkar…Job  │
└─────────────────────────────────────────────────────────────┘
```

**قاعدة ذهبية:** مسار الـ HTTP لا ينفّذ منطق البوت. يحفظ التحديث ويرد 200 بسرعة، ثم الـ worker يعالج.

في التطوير المحلي، الأمر `telegram:poll` يتجاوز الـ webhook ويستدعي `TelegramUpdateProcessor` مباشرة (بدون جدول `telegram_updates`).

## 6. قاعدة البيانات

### 6.1 الجداول الأساسية

| الجدول | النموذج | الدور |
|---|---|---|
| `users` | `User` | هوية تيليغرام + الإعدادات + مواعيد التذكير التالية + حالة الإعداد |
| `adhkar_collections` | `AdhkarCollection` | مجموعات: morning/evening × short/full + additional |
| `adhkar_items` | `AdhkarItem` | ذكر واحد (نص، تكرار، فضل، مصدر…) |
| `adhkar_collection_items` | pivot | ربط مرتّب بين المجموعة والذكر |
| `reminder_logs` | `ReminderLog` | سجل ادّعاء/إرسال لكل مستخدم/نوع/يوم |
| `telegram_updates` | `TelegramUpdate` | صندوق وارد الـ webhook (فريد بـ `update_id`) |
| `jobs`, `failed_jobs`, `job_batches`, `cache`, `sessions` | Laravel | الطابور والكاش والجلسات |

**لا يوجد** جدول منفصل لـ `user_settings` أو `onboarding_sessions`؛ كل شيء على `users`.

### 6.2 أهم أعمدة `users`

| العمود | المعنى |
|---|---|
| `telegram_id` | معرّف المستخدم في تيليغرام (فريد) |
| `chat_id` | معرّف المحادثة للإرسال (فريد) |
| `timezone` | معرّف IANA مثل `Asia/Damascus` |
| `morning_time` / `evening_time` | الوقت المحلي المفضّل |
| `mode` | `short` أو `full` |
| `reminders_enabled` | هل التذكير مفعّل؟ |
| `onboarding_state` | مرحلة الإعداد |
| `awaiting_input` | انتظار إدخال نص حر (دولة/وقت مخصص) |
| `next_morning_at` / `next_evening_at` | أقرب موعد إرسال **بتوقيت UTC** |
| `paused_at` | وقت الإيقاف اليدوي |
| `last_interaction_at` | آخر تفاعل |

### 6.3 أهم أعمدة `reminder_logs`

| العمود | المعنى |
|---|---|
| `user_id`, `reminder_type` | من ولأي نوع (صباح/مساء) |
| `scheduled_local_date` | تاريخ اليوم المحلي للمستخدم |
| `scheduled_for` | اللحظة المجدولة |
| `collection_key` | مثل `morning_short` |
| `status` | `pending` → `sent` / `failed` / `completed` |
| `telegram_message_id` | IDs الرسائل المرسلة (JSON) |
| `content_version_map` + `content_snapshot_hash` | لقطة المحتوى عند ضغط «ابدأ»، قبل إرسال الأجزاء |
| `dispatch_attempts` | محاولات الاسترداد |

### 6.4 القيود المهمة

- `users.telegram_id` و `users.chat_id` فريدان.
- `reminder_logs` فريد على `(user_id, reminder_type, scheduled_local_date)` → يمنع إرسال صباحين في نفس اليوم المحلي.
- `telegram_updates.update_id` فريد → webhook idempotent.
- فهارس على `(reminders_enabled, next_morning_at)` و `(reminders_enabled, next_evening_at)` لتسريع الاستعلام عن المستحقين.

### 6.5 العلاقات

```text
User 1───* ReminderLog
AdhkarCollection *───* AdhkarItem  (عبر adhkar_collection_items مع order)
```

مجموعات `*_full` تعيد استخدام عناصر المختصر عبر الـ pivot وتضيف عناصر إضافية.

## 8. دورة حياة رسالة تيليغرام

### 8.1 مسار الإنتاج (Webhook)

1. تيليغرام يرسل `POST` إلى:
   ```text
   {APP_URL}/telegram/webhook/{TELEGRAM_WEBHOOK_SECRET}
   ```
2. الوسيط `VerifyTelegramWebhookSecret` يتحقق من:
   - السر في المسار
   - الترويسة `X-Telegram-Bot-Api-Secret-Token`
   بمقارنة آمنة `hash_equals`. أي خلل → **403**.
3. يوجد throttle: `telegram-webhook` (30 طلب/دقيقة حسب chat أو IP).
4. `TelegramWebhookController`:
   - بدون `update_id` → **400**
   - يحفظ صفًا في `telegram_updates` بحالة `pending` داخل معاملة
   - يطلق `ProcessTelegramUpdateJob`
   - تكرار نفس `update_id` → **200** بدون صف ثانٍ
   - النجاح دائمًا **200** سريعًا (لا منطق بوت هنا)
5. الـ worker يشغّل الـ job:
   - `ShouldBeUnique` حسب معرّف التحديث
   - tries=3، backoff `[5, 30, 120]`
   - الحالة: `processing` → استدعاء المعالج → `processed` أو `failed`

### 8.2 مسار التطوير (Long polling)

```bash
php artisan telegram:poll
```

- يستدعي `getUpdates` بانتظار طويل.
- يمرّر كل تحديث مباشرة إلى `TelegramUpdateProcessor::handle`.
- **لا** يكتب في `telegram_updates` و**لا** يحتاج `queue:work` لهذا المسار.
- **شرط:** نسخة poll واحدة فقط؛ نسختان → خطأ Conflict من تيليغرام.
- **شرط:** لا webhook نشط مع الـ poll؛ استخدم:
  ```bash
  php artisan telegram:webhook:set --unset
  ```

## 9. معالج التحديثات

الملف المركزي: `app/Services/Telegram/TelegramUpdateProcessor.php`.

### 9.1 عند كل تحديث

1. بناء DTO من الحمولة (`App\Support\Telegram\TelegramUpdate`).
2. إيجاد أو إنشاء `User` حسب `telegram_id`.
3. تحديث `chat_id` و`first_name` و`username` و`last_interaction_at`.

   - إن وُجد **callback query** → `handleCallback` / `routeCallback`

## 10. مسار الإعداد الأولي (Onboarding)

الخدمة: `OnboardingService` + إكمال عبر `UserSettingsService::completeOnboarding`.

### 10.1 آلة الحالات

```text
new
  │ /start
  ▼
waiting_timezone  ──(دولة أو نص حر)──► waiting_morning_time
  │                                       │
  │                                       ▼
  │                                 waiting_evening_time
  │                                       │
  │                                       ▼
  │                                 waiting_mode
  │                                       │
  │                                       ▼
  └──────────────────────────────── completed
         (reminders_enabled = true + next_*_at محسوبة)
```

### 10.2 تفاصيل كل خطوة

1. **الدولة / المنطقة الزمنية**
   - أزرار من `config('adhkar.timezones')` (أسماء دول).
   - زر **دولة أخرى** → يطلب كتابة اسم البلد بالعربي.
   - الحل عبر `TimezoneCatalog::resolve` ثم حفظ `users.timezone`.

2. **وقت الصباح**
   - أزرار من `morning_presets` (مثل 05:00 … 07:00) + **وقت آخر** بصيغة `HH:MM`.

3. **وقت المساء**
   - أزرار من `evening_presets` + وقت مخصص بنفس التحقق.

4. **النسخة**
   - مختصر أو كامل → `completeOnboarding`.

### 10.3 قيم `awaiting_input`

| القيمة | المعنى |
|---|---|
| `onboarding:timezone_custom` | نص دولة أثناء الإعداد |
| `onboarding:morning_time_custom` | وقت صباح حر |
| `onboarding:evening_time_custom` | وقت مساء حر |
| `settings:timezone_custom` | نفس الفكرة من الإعدادات |
| `settings:morning_time_custom` / `settings:evening_time_custom` | تعديل الأوقات لاحقًا |

### 10.4 متى يُعتبر المستخدم «مكتمل الإعداد»؟

`User::isOnboarded()`:

- `onboarding_state === completed`
- و`timezone` و`morning_time` و`evening_time` كلها مملوءة

## 11. الإعدادات والإيقاف/الاستئناف

الخدمة: `UserSettingsService`.

| العملية | الأثر |
|---|---|
| تعديل المنطقة أو الوقت | حفظ + `recalculateNextReminders` |
| تعديل الوضع short/full | حفظ فقط (يظهر في التذكير التالي عبر `collection_key`) |
| `pause` | `reminders_enabled=false`، تصفير `next_*_at`، حفظ `paused_at` |
| `resume` | تفعيل + إعادة حساب المواعيد |
| `toggleReminders` | pause أو resume حسب الحالة الحالية |

الإيقاف **لا يمسح** الدولة والأوقات والنسخة؛ يمكن الاستئناف متى شاء المستخدم.

## 12. المنطقة الزمنية واختيار الدولة

### 12.1 لماذا الدولة وليس المدينة؟

معظم الدول العربية لها منطقة زمنية واحدة. اسم الدولة أسهل لكبار السن وغير المتمرسين من أسماء مدن أو صيغة `Asia/Damascus`.

القائمة الحالية (أمثلة): سوريا، لبنان، الأردن، فلسطين، العراق، مصر، السعودية، الإمارات، الكويت، قطر، البحرين، عُمان، اليمن، السودان، ليبيا، تونس، الجزائر، المغرب، تركيا، بريطانيا، فرنسا، أمريكا.

كل زر يخزّن داخليًا معرّف IANA (مثل `Asia/Damascus` لسوريا). رسالة التأكيد قد تعرض المعرّف التقني؛ الواجهة للمستخدم عربية.

### 12.2 الكتابة اليدوية (`TimezoneCatalog`)

الترتيب عند الحل:

1. مطابقة حرفية لمعرّف IANA صالح.
2. مطابقة حرفية لمفتاح في `timezone_aliases`.
3. مطابقة بعد **تطبيع** النص مقابل قائمة المناطق / اسم المدينة في المسار.
4. مطابقة **تقريبية (fuzzy)** بـ `levenshtein` على الأسماء المطبّعة (تسامح حرف أو حرفين للأسماء الأطول).

**التطبيع يشمل:**

- حذف التشكيل والتطويل.
- توحيد أ/إ/آ → ا، ة → ه، ى → ي.
- إسقاط «ال» التعريف في بداية الكلمة.
- تحويل لأحرف صغيرة (للأقسام اللاتينية).

**أمثلة تعمل:** حلب، الامارات، السعوديه، دمشقق (خطأ طباعة)، عُمان ≠ عمان (الأولى مسقط، الثانية عمّان/الأردن بعد التطبيع الدقيق للضمة في قاموس الـ aliases).

النصوص في `lang/ar/bot.php` تشجّع الكتابة بالعربي (`سوريا، مصر، السعودية`) ولا تعرض مثال IANA كخيار أول.

## 13. الأزرار وترتيب RTL

الملف: `app/Support/Telegram/KeyboardFactory.php`.

تيليغرام يرسم أزرار الصف **من اليسار لليمين** دائمًا. لذلك الدالة الخاصة `rtl($row)` تعكس ترتيب عناصر الصف بـ `array_reverse` حتى يظهر الخيار المنطقي الأول في **أقصى اليمين** للقارئ العربي.

تُطبَّق على صفوف:

- خيارات الدول
- أوقات الصباح/المساء
- مختصر/كامل
- صفوف الإعدادات متعددة الأزرار
- قائمة أذكار اليوم
- لوحة الرد الرئيسية (حيث يوجد أكثر من زر في الصف)

ترتيب **الصفوف من الأعلى للأسفل** لا يُعكس؛ فقط الترتيب داخل الصف الأفقي.

## 14. نظام التذكيرات بالتفصيل

### 14.1 حساب الموعد التالي

`ReminderScheduleCalculator`:

1. يبني مرشّحًا لوقت اليوم في **منطقة المستخدم**.
2. إن كان الموعد قد مضى بالنسبة للحظة المرجعية (UTC)، يضيف يومًا.
3. يعيد `Carbon` بـ **UTC** ليُخزَّن في `next_morning_at` / `next_evening_at`.

يتعامل مع منتصف الليل وتحويل التوقيت الصيفي ضمن حدود PHP timezone DB.

### 14.2 الادّعاء (Claim) كل دقيقة

الأمر: `adhkar:dispatch-due-reminders` → `ReminderDispatchService`.

لكل مستخدم مستحق (`reminders_enabled` وموعده حان):

1. داخل **معاملة واحدة**:
   - إدراج `reminder_logs` بحالة `pending` و`collection_key` المناسب.
   - تقديم `next_*_at` إلى الحدوث التالي.
2. إن كسر القيد الفريد (نفس اليوم) → تجاهل بهدوء (لا إرسال مزدوج).
3. **بعد** نجاح الـ commit فقط: `SendAdhkarReminderJob::dispatch`.

مفتاح المجموعة:

```text
{morning|evening}_{short|full}
```

حسب `AdhkarContentService::collectionKey`.

### 14.3 الإرسال

`SendAdhkarReminderJob` (`ShouldBeUnique` حسب log id) يرسل **تنبيهًا قصيرًا** فقط، مع زر «ابدأ الأذكار». عند نجاح الإرسال تصبح الحالة `sent`، وتبقى لقطة المحتوى فارغة.

`reminder_stale_minutes` (الافتراضي 3 دقائق) يجب أن يبقى أطول من مهلة HTTP لتيليغرام مع زمن الطابور وهامش معالجة، حتى لا يتسابق الاسترداد مع طلب ما زال قيد الإرسال.

عند «ابدأ»:

1. التحقق أن السجل للمستخدم نفسه، وأن `scheduled_local_date` ما زال اليوم حسب منطقته الحالية.
2. قفل الصف، ثم حفظ `reading_started_at` ولقطة `collection_key` **قبل** أي جزء. المجموعة هي التي خُزّنت عند الجدولة، لا وضع المستخدم الحالي.
3. بعد الـ commit تُرسل الأجزاء (حوالي 3–4 أذكار، دون شطر ذكر). الزر «تم» على آخر جزء فقط.
4. ضغطة ثانية لا تعيد الإرسال. إذا فشل جزء لاحق تبقى اللقطة، وتظهر رسالة هادئة مع زر أذكار اليوم، بلا تفاصيل تقنية.

`/today` يفتح القائمة ثم يبدأ القراءة فورًا من الوضع الحالي، بلا سجل تذكير وبلا زر تم.

### 14.4 الاسترداد (Recovery)

- سجل `pending` بلا `last_dispatch_attempt_at` وأقدم من النافذة: يُعاد إرساله إلى الطابور.
- محاولة إرسال سُجّلت وما زال السجل `pending` بعد النافذة: يُعلَّم `nudge_unconfirmed` ولا يُرسل تنبيه ثانٍ.
- فشل Telegram API يمكن أن تعيد المحاولة عبر الوظيفة نفسها. حظر المستخدم يبقي الفشل ويعطّل التذكير.
- تحديثات `telegram_updates` العالقة تُعاد إلى الطابور بنفس الأمر.

لا يوجد استئناف لورد انقطع في منتصف القراءة في هذا الإصدار.

### 14.5 ما لا يُجدول أبدًا

**الأذكار الإضافية** تصفّح فقط؛ لا تدخل حلقة التذكير التلقائي.

## 16. تنسيق رسائل الأذكار (HTML)

### 16.1 الإرسال

`TelegramClient::sendMessage` و`editMessageText` يضعان دائمًا:

```text
parse_mode = HTML
```

### 16.2 بناء الرسالة

`AdhkarContentService::formatItem` / `buildMessages`:

- عنوان المجموعة في أول القطعة.
- لكل ذكر:
  - عنوان غامق: `<b>الرقم. العنوان</b>`
  - سطر التكرار مع رمز 🔁 إن وُجد
  - نص الذكر عادي (بعد تهريب HTML)
  - الفضل داخل `<blockquote>`؛ إن تجاوز ~200 حرف → `<blockquote expandable>`
  - المصدر بخط مائل `<i>` مع رقم الحديث والحكم (`hadith_grade`) مدمجين في نفس السطر عند توفرهما
- تهريب عبر `htmlspecialchars` لأي نص مستخدم داخل الوسوم.
- تقسيم الرسائل عند تجاوز `message_limit` (3900 حرفًا تقريبًا).
- تذييل مناسب (صباح / مساء / إضافية).

### 16.3 الوضع التفصيلي `detailed: true`

يُستخدم عند فتح ذكر إضافي منفردًا:

- يعرض **الراوي** إن وُجد.
- يعرض **ملاحظة التوجيه** (`guidance_note`) إن وُجدت.

أذكار الصباح/المساء المجمّعة تبقى مختصرة (بدون هذين الحقلين) حتى لا تطول الرسالة اليومية.

## 21. الأمان

1. التوكن والسر من البيئة فقط؛ لا يُثبتان في الكود.
2. مسار الـ webhook يحتوي السر + ترويسة سر تيليغرام (`hash_equals`).
3. Rate limiting على الـ webhook.
4. الـ controller يرد 200 بسرعة لتقليل عواصف إعادة المحاولة من تيليغرام.
5. لا يجب طباعة التوكن في اللوجات (احذر من رسائل أخطاء cURL التي تضم التوكن في الرابط).
6. عند حظر البوت من المستخدم: تعطيل تذكيراته تلقائيًا.
7. في حال تسرّب التوكن (مثل ظهوره في طرفية): أعد توليده من BotFather فورًا وحدّث `.env`.

## 22. التشغيل المحلي

### 22.1 الإعداد لأول مرة

```bash
composer install
copy .env.example .env
php artisan key:generate
php artisan migrate
php artisan adhkar:sync
```

ضع في `.env`:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_WEBHOOK_SECRET` (حتى لو كنت تستخدم poll محليًا لفحوص أخرى)

### 22.2 أسهل طريقة للاختبار الحي

```bash
php artisan telegram:webhook:set --unset
php artisan telegram:poll
```

ثم من تيليغرام: `/start` وجرّب المسارات.

**قائمة تحقق بعد تحسينات UX:**

1. قائمة الدول تظهر لا المدن.
2. «دولة أخرى» تقبل أسماء عربية (حلب، الامارات…).
3. أوقات الصباح تبدأ من اليمين (أبكر وقت يمينًا).
4. رسائل الورد: عنوان غامق، فضل باقتباس، مصدر مائل.
5. ذكر إضافي منفرد يظهر الراوي/الملاحظة عند توفرها.
6. الإعدادات وتبديل التذكير يعملان.

### 22.3 مشاكل شائعة محليًا

| العرض | السبب / الحل |
|---|---|
| `cURL error 28` / SSL timeout | الشبكة لا تصل `api.telegram.org` (VPN / شبكة أخرى) |
| `Conflict: terminated by other getUpdates` | أكثر من `telegram:poll` أو webhook ما زال مسجّلًا |
| `/start` بلا رد مع webhook | الـ worker متوقف؛ شغّل `queue:work` |
| محتوى فارغ | شغّل `adhkar:sync` |

للتحقق من الشبكة:

```powershell
curl.exe -I https://api.telegram.org
```

إيقاف كل عمليات الـ poll المكررة في PowerShell ثم تشغيل واحدة فقط.

### 22.4 مسار webhook محلي (أقرب للإنتاج)

يحتاج HTTPS عامًا (ngrok أو مشابه) ثم:

```bash
php artisan serve
php artisan queue:work --tries=3 --backoff=5,30,120
php artisan telegram:webhook:set
php artisan adhkar:smoke --live
```

## 26. أسئلة شائعة ومشاكل معروفة

**هل يمكن اختيار الساعة بدون تحديد الدولة و«نستنتج» المنطقة؟**  
لا. الساعة وحدها لا تحمل معلومة جغرافية. الحل العملي: اختيار دولة، أو كتابة اسم البلد، أو (مستقبلًا) مشاركة الموقع GPS — غير منفّذة حاليًا.

**لماذا تظهر `Asia/Damascus` بعد اختيار سوريا؟**  
لأن التخزين الداخلي يستخدم IANA. يمكن لاحقًا إظهار اسم الدولة المخزَّن للمستخدم بدل المعرّف التقني في رسائل التأكيد.

**هل الأذكار الإضافية تصل كإشعار يومي؟**  
لا. تصفح يدوي فقط.

**ماذا يحدث إذا تغيّر نص ذكر بعد إرسال تذكير؟**  
سجل التذكير يحتفظ بلقطة الإصدار وقت الإرسال؛ تغيير المحتوى لا يعيد كتابة الماضي.

**هل يكفي `php artisan test` للاطمئنان بعد تعديل UX؟**  
يغطي المنطق. التجربة البصرية (RTL، الاقتباسات، سهولة اختيار الدولة) تحتاج تجربة حية عبر `telegram:poll` أو الإنتاج.

البوت Laravel عربي يستقبل تحديثات تيليغرام، يكمل إعداد المستخدم (دولة ← أوقات ← نسخة)، يجدول تذكيرين يوميين بموثوقية claim + قيد فريد، ويرسل وردًا موثّقًا من قاعدة بيانات مزامَنة من ملفات ثابتة، مع واجهة أزرار مناسبة للقراءة من اليمين وتنسيق HTML يميّز الفضل عن المتن.

---

*هذا التقرير وصفي لحالة المستودع؛ لأي تغيير سلوكي لاحق يُفضَّل تحديث الأقسام ذات الصلة أو الوثائق القصيرة في `docs/`.*
